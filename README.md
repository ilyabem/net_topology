# Сканер и редактор топологии сети

[![Tests](https://github.com/ilyabem/net_topology/actions/workflows/tests.yml/badge.svg)](https://github.com/ilyabem/net_topology/actions/workflows/tests.yml)
[![Python](https://img.shields.io/badge/python-3.10%2B-blue.svg)](https://www.python.org/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Platform](https://img.shields.io/badge/platform-Linux%20%7C%20Windows%20%7C%20macOS-lightgrey.svg)]()

Инструмент находит устройства в сети, определяет их тип, производителя и ОС,
строит иерархическую схему (шлюз → коммутатор → устройства) без наложений
и выгружает её в переносимые форматы: интерактивный HTML, SVG, PDF, draw.io,
GraphML, CSV.

---

## Возможности

- **Классификация** по взвешенному голосованию признаков: MAC-производитель
  (OUI-база ~58 000 записей, включая подблоки MA-M/MA-S), открытые порты,
  имя хоста, SNMP sysDescr, TTL. Для каждого устройства — процент
  уверенности и пояснение «почему такой тип».
- **ОС**: Windows / Windows Server, Linux (Ubuntu, Debian, RHEL, Astra, РЕД ОС…),
  macOS, iOS, Android, Cisco IOS/IOS XE/NX-OS, MikroTik RouterOS, Junos,
  FortiOS, pfSense, Synology DSM, VMware ESXi и др.
- **Расположение в сети**: число L3-хопов от сканера (по TTL), шлюз подсети,
  цепочка маршрутизаторов до удалённых подсетей.
- **19 типов устройств**, включая точки доступа, IP-камеры, NAS и IoT.
- **Читаемая схема**: дерево сверху вниз или слева направо, органическая
  раскладка. Карточки никогда не перекрываются, а связи идут по зазорам
  и не проходят через чужие узлы (проверяется тестами).
- **Удобный GUI**: список устройств по подсетям с поиском, панель свойств,
  журнал, прогресс и остановка сканирования, фильтр типов, векторные иконки,
  масштаб колесом под курсором, сохранение настроек между запусками.

## Установка

### Шаг 1 — Системные зависимости

#### Linux (Debian / Ubuntu)

```bash
# nmap — сканер портов
sudo apt install -y nmap

# Библиотеки Qt для работы GUI
sudo apt install -y \
    libxcb-cursor0 libxcb-xinerama0 libxcb-icccm4 libxcb-image0 \
    libxcb-keysyms1 libxcb-randr0 libxcb-render-util0 libxcb-shape0 \
    libxcb-xfixes0 libxcb-xkb1 libxkbcommon-x11-0 libgl1 libglib2.0-0
```

#### macOS

```bash
brew install nmap
```

#### Windows

- **nmap**: https://nmap.org/download.html
- **Npcap**: https://npcap.com/ (отметить «WinPcap API-compatible mode»)

### Шаг 2 — Виртуальное окружение и пакеты

```bash
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate.bat
pip install -r requirements.txt
```

| Пакет | Назначение |
|---|---|
| `networkx` | Граф топологии |
| `PyQt5` | Графический интерфейс, иконки (QtSvg), экспорт PDF |
| `python-nmap` | Обёртка над системным nmap |
| `scapy` | ARP-сканирование L2 (требует root / Администратора) |
| `pysnmp==4.4.12` | SNMP-опрос (ставится только на Python ≤ 3.11) |
| `mac-vendor-lookup` | Резервное определение производителя |
| `pytest` | Тесты |

> `numpy` больше не нужен — раскладка написана на чистом Python.

## Использование

### GUI

```bash
python net_topology.py                               # пустое окно
python net_topology.py --subnet 192.168.1.0/24       # сканировать и открыть
python net_topology.py --load topology.json          # открыть проект
```

### Несколько подсетей

```bash
python net_topology.py --subnets 192.168.1.0/24 10.0.0.0/24
python net_topology.py --subnets 192.168.1.0/24,10.0.0.0/24 --parallel
```

### Без GUI, с выгрузкой

```bash
python net_topology.py --subnet 192.168.1.0/24 --no-gui --export network.html --export network.drawio
python net_topology.py --load topology.json --no-gui --layout tree-lr --export network.svg
```

### Все аргументы

| Аргумент | Описание |
|---|---|
| `--subnet CIDR` | Одна подсеть |
| `--subnets CIDR [CIDR ...]` | Несколько подсетей (пробел или запятая) |
| `--community STRING` | SNMP community (по умолчанию `public`) |
| `--no-gui` | Только вывод в консоль |
| `--max-hosts N` | Ограничение хостов на подсеть (по умолчанию 254) |
| `--timeout SEC` | Таймаут ответа хоста (по умолчанию 1.0) |
| `--parallel` | Параллельное сканирование подсетей |
| `--load FILE` | Открыть проект JSON |
| `--layout MODE` | `tree` (по умолчанию), `tree-lr`, `organic`; с `--load` перекладывает схему |
| `--export FILE` | Экспорт по расширению: `.html .svg .drawio .graphml .csv .json` (можно несколько раз) |
| `--output FILE` | Сохранить проект JSON |
| `--output-graphml FILE` | Экспорт GraphML |
| `--update-oui` | Обновить OUI-базу и выйти |

## Работа с GUI

### Панели

- **Сканирование** — подсети (кнопка «Моя» подставляет подсеть компьютера),
  community, таймаут, лимит хостов, прогресс; «Стоп» завершает работу после
  текущей подсети.
- **Устройства** — дерево по подсетям: имя, IP, тип, производитель, ОС.
  Клик выделяет узел на схеме, двойной клик открывает свойства.
- **Свойства** — сведения о выбранном устройстве и пояснение, почему выбран
  такой тип.
- **Журнал** — ход сканирования.

Панели можно перемещать, закрывать и вновь открывать через меню **Вид**.
Расположение панелей и параметры сканирования сохраняются между запусками.

### Схема

- Карточка устройства: иконка типа, имя, IP, «производитель · ОС».
- Бейджи: **GW** — шлюз подсети, **★** — несколько интерфейсов,
  **RDP / SSH / TEL / VNC / WRM / SNMP** — открытые службы.
- Цветные пунктирные зоны — подсети (CIDR и число устройств).
- Стиль линии показывает источник связи: LLDP/CDP, таблица MAC коммутатора,
  ARP, маршрут (traceroute), предполагаемая, ручная. Легенда: **Справка → Обозначения**.
- При сильном отдалении подписи скрываются и остаются крупные иконки.

### Управление

| Действие | Как |
|---|---|
| Масштаб | Колесо мыши (под курсором), `Ctrl +` / `Ctrl −` |
| Вписать / 100% | `F` / `Ctrl+0` |
| Панорама | Средняя кнопка мыши или пробел + ЛКМ |
| Переместить узел / подсеть | ЛКМ / `Shift` + ЛКМ |
| Свойства | Двойной клик или ПКМ → Редактировать |
| Добавить связь | `Ctrl+K`, затем клик по двум узлам |
| Удалить связь | `Ctrl` + клик по связи |
| Удалить выбранное | `Delete` |
| Поиск | `Ctrl+F`; `Enter` — следующее совпадение |
| Перестроить раскладку | `Ctrl+L` |
| Открыть проект | Перетащить `.json` в окно |

Если сдвинуть узел вручную, его связи остаются ортогональными:
узел заново подключается к шине своего уровня.

## Как строится схема

1. Устройства всех подсетей объединяются: дубликаты по IP; мультиинтерфейсные
   устройства — по общему MAC. Если за одним MAC много адресов одной подсети
   (proxy-ARP), объединения не происходит.
2. Шлюз подсети: шлюз из маршрута, затем мультиинтерфейсный маршрутизатор,
   затем маршрутизатор на адресе `.1` / `.254`.
3. Достоверные связи (LLDP, CDP, таблица MAC, ARP) важнее предполагаемых.
   Недостающие связи достраиваются так: шлюз → коммутаторы → устройства.
   Если коммутатор в подсети один, устройства подключаются к нему.
   Если нет ни шлюза, ни коммутатора, создаётся узел «Сегмент сети».
4. Раскладка: остовное дерево от ближайшего к сканеру шлюза. Каждая ветка
   занимает свою полосу. Если у узла много «листьев», они укладываются
   сеткой с соотношением сторон, близким к экрану.

## Как определяется тип устройства

Используется **взвешенное голосование**: побеждает тип с наибольшей суммой весов.

| Источник | Макс. вес | Пример |
|---|---|---|
| Однозначные порты | 15 | 9100 → printer, 5060 → voip_phone, 1433 → windows_server |
| SNMP sysDescr | 12 | «Cisco IOS», «Windows Server 2019», «Synology» |
| Ключевые слова в имени хоста | 12 | `iphone`, `pfsense`, `DESKTOP-…`, `WIN-…` |
| Порты | до 9 | Winbox 8291 → MikroTik, RTSP 554 → камера, Kerberos 88 → контроллер домена |
| OUI-производитель | 6.5 | Hikvision → ip_camera, Fortinet → firewall, Kyocera → printer |
| Шлюз подсети / адрес `.1`, `.254` | 6 / 4.5 | → router |
| Семейство ОС | 3 | Windows + серверные службы → windows_server |
| TTL | 2 | 64 → Linux/Unix, 128 → Windows, 255 → сетевое оборудование |

Короткие слова в имени хоста (`gw`, `sw`, `ap`, `fw`) сравниваются как
отдельные слова: `gwen-laptop` не станет шлюзом. Случайный (LAA) MAC
учитывается, только если производитель по OUI не найден.

## OUI-база производителей

Хранится в `data/oui_db.json`, скачивается при первом запуске и обновляется
автоматически, если старше 60 дней.

| Источник | URL |
|---|---|
| Wireshark manuf (основной) | https://www.wireshark.org/download/automated/data/manuf |
| IEEE OUI CSV (резервный) | https://standards-oui.ieee.org/oui/oui.csv |

```bash
python net_topology.py --update-oui      # или: Правка → Обновить OUI-базу
```

## Устранение проблем

### SNMP не работает на Python 3.12+

`pysnmp 4.4.12` несовместим с Python 3.12+ (там удалён модуль `asyncore`).
Установите системный `snmpget` — программа подхватит его автоматически:

```bash
sudo apt install snmp          # Linux
brew install net-snmp          # macOS
```

### Устройство определено неверно

Двойной клик по узлу → выберите правильный тип → **Ctrl+S**. Вручную заданный
тип получает уверенность 100%. При новом сканировании он будет определён
заново.

### GUI не открывается (ошибка xcb)

```bash
sudo apt install -y \
    libxcb-cursor0 libxcb-xinerama0 libxcb-icccm4 libxcb-image0 \
    libxcb-keysyms1 libxcb-randr0 libxcb-render-util0 libxcb-shape0 \
    libxcb-xfixes0 libxcb-xkb1 libxkbcommon-x11-0 libgl1
```

### Нет дисплея (SSH без X11)

Используйте `--no-gui --export network.html` и откройте HTML на любом компьютере.
